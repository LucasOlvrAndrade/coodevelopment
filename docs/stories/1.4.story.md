## Story

**As a** usuário,
**I want** ver como sugestão os meus mútuos do GitHub que já usam o app,
**so that** eu ache meus amigos sem digitar nada.

## Acceptance Criteria

1. A tela de adicionar amigos lista os mútuos (sigo e me seguem) que têm conta
   no app e ainda não são amigos nem têm pedido pendente (FR3).
2. Cada sugestão tem um botão que manda o pedido; nada vira amizade sem aceite.
3. Mútuos sem conta no app não aparecem.
4. A lista funciona com contas que seguem muita gente (paginação da API do
   GitHub).

## Escopo, dependências e riscos

**Entra:** regra `sugerirMutuos` (seguidores e seguidos do GitHub cruzados com quem tem conta, tirando amigos e pedidos pendentes nos dois sentidos); área "Sugestões" em "Adicionar", acima da busca, com o botão de pedir amizade; estado vazio que destaca a busca; erro do GitHub sem derrubar o resto da tela.

**Fica de fora:** convite para quem não usa o app (D12: sem link de convite); sugestões fora dos mútuos; guardar as sugestões em cache entre visitas (só se o custo aparecer).

**Depende de:** Story 1.3 (pedido de amizade e tela de Amigos) e 1.2 (token do GitHub com a permissão Followers).

**Complexidade:** média.

**Riscos:** (1) conta que segue milhares de pessoas gera dezenas de chamadas por visita (mitigado abaixo); (2) a renovação do token pode falhar (`reautenticar`), e a tela tem de continuar funcionando sem as sugestões; (3) o GitHub limita chamadas por hora por usuário (5.000 com token de usuário de GitHub App).

**Pronto quando:** os 4 ACs cobertos por testes (regra com GitHub simulado e banco PGlite, componente e E2E sem sessão), sugestões aparecendo em produção para a conta do Lucas quando o mútuo tiver conta, e lint, tipos e testes passando.

- Renderizar a página inteira no Vitest trava estados: testar componentes cliente direto.

### Mútuos com poucas chamadas

[Source: decisoes.md D12, architecture/external-apis.md]

- D12: mútuo = quem a pessoa segue **e** a segue de volta (`GET /user/following` cruzado com `GET /user/followers`, com o token do login), só os que têm conta no app, como sugestão (nada vira amizade sozinho).
- Para não pagar as duas listas inteiras de quem segue muita gente (AC 4): `GET /user` traz `followers` e `following`; buscar inteira só a lista menor (paginada com `per_page=100`), cruzar com quem tem conta pelo `github_id` (consulta única com `in`) e, para esses poucos, conferir a outra direção um a um: `GET /user/following/{login}` (204 sigo, 404 não sigo) ou `GET /users/{login}/following/{meu login}` (204 me segue).
- Limite de segurança: no máximo 50 páginas (5.000 contas) na lista menor; passou disso, usa o que veio e anota no log (sem erro para a pessoa).
- Casar sempre pelo id numérico do GitHub, nunca pelo login (o login muda; `user.login` não é único no banco).

### Correções 2026-10-27 (Dex, @dev, via Claude)

- **PERF-001:** a regra virou duas partes, `mutuosComConta` (GitHub) e `filtrarSugestoes` (banco); a primeira fica 5 minutos guardada por pessoa num cache em memória da instância (`servidor/cache-memoria.ts`), e a segunda roda sempre (`0f89c15`).
- **REL-001:** conferências em lotes de 5 com `Promise.allSettled`; a que falha só tira aquela pessoa e vai para o log.
- **PROD-001:** desfazer a amizade conta como recusa de quem desfez (A10 atualizada); a pessoa não volta como sugestão, mas ainda pode pedir (`db70a71`).
- **TEST-001:** `SugestoesMutuos` foi para `componentes/amigos` com teste do cache, de `reautenticar`, do erro genérico e do redirect do Next.

### Reavaliação 2026-10-27 (Quinn, @qa, via Claude): PASS

Achados corrigidos com teste. Pendente fora do gate: abrir `/amigos` logado com uma conta de verdade do GitHub (ação do Lucas).
