## Story

**As a** criador,
**I want** criar uma jam já criando um repositório novo na minha conta,
**so that** a gente comece um projeto do zero.

## Acceptance Criteria

1. A tela de nova jam permite informar nome e visibilidade do repositório novo.
2. O repositório é criado na conta do criador, com um commit inicial.
3. A jam é criada ligada a ele, como na 2.1.
4. Nome de repositório já existente mostra erro claro, sem criar nada.

## Escopo, dependências e riscos

**Entra:** escolha "Importar repositório | Criar repositório" na nova jam; formulário com nome e visibilidade (privado por padrão); criar o repositório com commit inicial (`auto_init`); criar a jam ligada a ele com as regras da 2.1; conferir antes se a instalação do app cobre todos os repositórios.

**Fica de fora:** descrição, licença e `.gitignore` do repositório novo; repositório em organização (D4: conta do criador); chamar amigos (2.3).

**Depende de:** Story 2.1 (tabelas, `criarJam`, tela de nova jam) e 1.2 (permissão Administration write).

**Complexidade:** média.

**Riscos:** (1) a instalação com "Only select repositories" não cobre o repositório recém-criado (pendência 2 da Story 1.2): a tela confere antes e pede "All repositories" com o link das configurações; (2) logo depois do `auto_init`, a branch pode demorar alguns instantes para responder (tentar de novo algumas vezes); (3) o repositório pode ser criado e a jam falhar (banco fora): a mensagem diz que o repositório existe e pode ser importado, sem apagar nada no GitHub.

**Pronto quando:** os 4 ACs cobertos por testes (regras com GitHub simulado e PGlite, componentes, E2E sem sessão), deploy no ar, e lint, tipos e testes passando.

## Dev Notes

### Previous Story Insights

- Story 2.1: `criarJam` confere o repositório no GitHub e grava jam e participante criador numa instrução só (A9), com o id tentando de novo em colisão e `jam_ja_existe` pelo índice (A11). Extrair a gravação para um trecho usado pelas duas regras.
- `githubRepositorios(octokit)` em `servidor/github.ts`; o Octokit codifica a barra do ref (`heads%2Fmain`), e a API aceita.
- Botões em `componentes/ui/botoes.ts`.
- Pendência 2 da 1.2: "Only select repositories" cobre repositório criado depois? A resposta do GitHub: não; só "All repositories" inclui os novos. Por isso a conferência da instalação antes de criar.

### GitHub

[Source: architecture/external-apis.md]

- `POST /user/repos` (`repos.createForAuthenticatedUser`) com `name`, `private`, `auto_init: true` (commit inicial com README). Permissão Administration write (já no app).
- Nome já usado na conta: 422 com "name already exists on this account".
- `GET /user/installations` (`apps.listInstallationsForAuthenticatedUser`): a instalação cuja `account.id` é o `githubId` da pessoa, com `repository_selection`; o link de configurações é `https://github.com/settings/installations/{id}`.

### Interface

[Source: front-end-spec.md (Nova jam; fluxo "Criar uma jam")]

- Escolha "Importar repositório | Criar repositório"; campos de nome e visibilidade no criar.
- Nome de repositório já existente: erro no próprio campo.

### Testing

- Regras contra PGlite com GitHub simulado: cria e grava a jam; nome inválido; nome repetido não grava nada; instalação parcial não cria; branch que demora; jam que falha depois do repositório criado.
- Componente: alternância, validação do nome, erro no campo.
