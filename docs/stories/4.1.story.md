## Story

**As a** participante,
**I want** ver quando o Claude de outra pessoa está trabalhando,
**so that** eu não precise perguntar.

## Acceptance Criteria

1. Ao entrar na jam, o conector instala ou atualiza o plugin do Claude Code
   para aquela pasta (escopo `local`, que não vai para o git), sem
   configuração manual (FR11). Se o Claude Code não estiver instalado, a
   sincronização segue e o terminal diz como instalar. Se ele já estiver
   aberto na pasta, o terminal diz para recarregar os plugins.
2. Quando o Claude de alguém recebe um prompt, a página da jam mostra para
   todos *"Claude Code de {nome} está trabalhando"* em até 1 s (FR12, NFR1).
   O texto do prompt não sai do PC (o resumo do que ele faz vem do `anunciar`,
   Story 4.2).
3. Quando ele termina, o status some; quando para por erro (limite de uso,
   autenticação, sobrecarga), a página mostra *"parou: {motivo}"* por alguns
   segundos e depois some. Fechar o conector ou o Claude Code também tira o
   status.
4. Os hooks falam só com o conector local (127.0.0.1, segredo por sessão),
   respondem em menos de 1 s mesmo sem conector, e nunca travam nem mudam o
   comportamento do Claude Code fora de uma jam (NFR5).
5. Teste de integração chama o script dos hooks com a entrada JSON
   documentada e confere o status que chega à sala.

## Escopo, dependências e riscos

**Entra:**
- Plugin (`packages/plugin`): `hooks/hooks.json` com `SessionStart`,
  `UserPromptSubmit`, `Stop`, `StopFailure` e `SessionEnd`, todos chamando
  `node ${CLAUDE_PLUGIN_ROOT}/scripts/hook.mjs` (sem dependências), que acha
  a jam pelo arquivo de descoberta da pasta (`CLAUDE_PROJECT_DIR` ou `cwd`,
  subindo até a raiz) e faz um POST curto ao conector.
- Conector: servidor HTTP local em porta aleatória com segredo por sessão,
  gravado no arquivo de descoberta; estado por sessão do Claude (várias
  sessões na mesma pasta); mensagem `status` para a sala; instalação do
  plugin por marketplace local (`claude plugin marketplace add ... --scope
  local` e `claude plugin install ... --scope local`); o plugin vai junto no
  pacote do npm. Versão 0.4.0.
- Protocolo: mensagem `status` (conector → sala) e `status` (sala →
  páginas, por pessoa).
- Sala: status guardado no estado de cada conexão do conector (sobrevive à
  hibernação), enviado às páginas ao abrir e a cada mudança; some quando o
  conector cai.
- Página: frase de status na faixa de cada participante, com marca animada
  (parada com movimento reduzido) e anúncio ao leitor de tela.

**Fica fora:** servidor MCP e `anunciar` (Story 4.2; o `.mcp.json` continua
vazio, e a aprovação do MCP na primeira vez vem com ele), contexto cruzado
(4.3), conflito (4.4).

**Riscos:** a interface de hooks do Claude Code muda (mitigado: teste com a
entrada documentada e conferência real com o Claude Code 2.1.316 desta
máquina); hook lento travando o prompt (mitigado: tempo curto no POST e saída
em silêncio).
