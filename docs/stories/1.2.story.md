## Story

**As a** desenvolvedor,
**I want** entrar no app com a minha conta do GitHub,
**so that** eu não precise de outra senha e o app possa agir no meu GitHub.

## Acceptance Criteria

1. O botão de entrar leva ao GitHub e volta logado.
2. O primeiro login cria o usuário com nome, usuário e foto do GitHub (FR1).
3. O token do GitHub fica só no servidor, cifrado (NFR8).
4. O usuário sai pelo menu; páginas internas exigem login.
5. O login usa o GitHub App com as permissões da arquitetura (NFR9); a
   instalação do app na conta acontece no mesmo passo do login.
6. A renovação do token do GitHub (validade de 8 h) acontece sozinha antes
   de cada chamada.

### Fluxo de login

Navegador → Better Auth → `authorize` do GitHub App (instalar + autorizar) → `code` → troca por token de usuário + refresh → cria ou atualiza `user` (githubId, login, nome, foto); tokens cifrados em `account` → cookie de sessão httpOnly, Secure, SameSite=Lax.
[Source: architecture/backend-architecture.md#auth-flow]

Página protegida: `auth.api.getSession({ headers: await headers() })` no `(app)/layout.tsx`; sem sessão, `redirect("/")`.
[Source: architecture/frontend-architecture.md#protected-route-pattern]

`exigirSessao()` aceita cookie do navegador; o Bearer do conector entra com o login por dispositivo (Story 3.1).
[Source: architecture/backend-architecture.md#middlewareguards]

- Instalação no mesmo passo do login, com "All repositories". **[verificar na Story 1.2]** se "selected repositories" inclui sozinho o repositório recém-criado.

### Permissão de e-mail (diferença encontrada ao criar a story)

A documentação do Better Auth diz que, com GitHub App, é obrigatório dar
**Email addresses: Read-only** em Account Permissions; sem isso o login
falha com `email_not_found`. E-mail primário privado também dá `email: null`
em `GET /user`; o fallback é ler `GET /user/emails`. Essa permissão não está
na tabela da arquitetura: o @architect deve incluí-la em `external-apis.md`
nesta story. O app não mostra nem usa o e-mail; ele só existe porque o
Better Auth exige.
[Fonte: better-auth.com/docs/authentication/github, consultado em 26/10/2026]

### Better Auth (verificado na documentação em 26/10/2026)

- `account.encryptOAuthTokens` (padrão `false`): cifra os tokens antes de gravar. A documentação não diz o algoritmo nem a chave; por isso a Task 3.
- `auth.api.getAccessToken` renova o token vencido antes de devolver; `refreshToken` força a renovação; a opção `refreshAccessToken` do provedor aceita função própria.
- Schema: `npx auth@latest generate` gera as tabelas para o Drizzle; depois `drizzle-kit generate` e `migrate`.
- Versão atual 1.7.13, MIT. A Tech Stack registrava 1.7.x (1.7.12 em 20/10).
[Fonte: better-auth.com/docs/concepts/oauth, /docs/reference/options, /docs/adapters/drizzle]
